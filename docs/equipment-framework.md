# Equipment framework — layered player sprites (paper-doll)

Status: design accepted (equipment base sheet + pipeline + render refactor).
Goal: player visuals become **data + art**, not code. Adding a helm, armor or
weapon must not touch `src/render.hpp`.

## Today (baseline)

`drawPlayer()` in `src/render.hpp` picks shapes with per-weapon branches and
computes every offset inline (see §10 of `build/checkpoint-review.md`):

| part | art today | positioning |
|---|---|---|
| body | `fxplayer` 16x16, 2 frames (normal/dodge), flat shapes incl. head+shadow | player top-left; center = `(x+8, y+8)` |
| sword | `fxslash` 32x32 (5 shapes by live `hw/hh`), `fxparry`, `fxchip` | `cx + (fx*reach)>>4`; reach x0.6 outside active |
| flail | `fxwhirl` (6 ring dots, chain, ball), `fxchip` | 20x14 ellipse at `whirlTick*14`; chain at `reach*i/4` |
| gun | `fxguard` 12x16 (plate/white/shove), `fxreload` | `cx + (fx*5)>>4`, origin = plate center -(6,8) |
| effects | `fxerase` (i-frames), `fxwhirl` dot (stun) | tick-driven |

No facing, no head/body split, no per-item data.

## Slots and draw order

```
SHADOW -> BODY -> HEAD -> WEAPON -> OFFHAND -> EFFECTS
```

`EFFECTS` (i-frame erase hole, stun sparkle, reload bar) may stay procedural
until their own bead; they are state overlays, not equipment.

## Facing and poses

- Facing = the existing 8-way `fp::dirIndex*` result (0=E, 1=SE, ... 7=NE).
  Art is baked per facing; render selects with one index.
- Pose = `(state, stance, phase)` collapsed to a small pose id per item:
  `idle | attack_startup | attack_active | attack_recover | parry | whirl |
  guard | shove | dodge | deflect | stun | dead`.
- `phase` for attacks is the existing `p.t < startup / < startup+active`
  split.

## Cart sheet layout, naming, anchors

Generated from `data/equipment/*.json`; PNGs live under `images/equip/` and are
declared through `fxdata/equip/Sprites.txt` (same flow as blocks/fonts/menu).

The base unit is a **player sheet**: one row, 8 facing cells (DIR8 order:
0=E, 1=SE, 2=S, 3=SW, 4=W, 5=NW, 6=N, 7=NE), cell = anchor center. Equipment
sets are drawn over that same layout. Layered per-slot sheets (below) are the
deferred option for mixed gear; when they land they use the same row layout.

| slot | cell | frames | layout |
|---|---|---|---|
| player | 16x16 | 8 | one row, facing 0..7 (base / equipment-set sheet) |
| shadow | 16x16 | 1 | — (deferred layer) |
| body | 16x16 | 8 | one row, facing 0..7 (deferred layer) |
| head | 16x16 | 8 | one row, facing 0..7 (deferred layer) |
| weapon | 32x32 | 24 | 8 facing columns x 3 phase rows (frame index = phase*8 + facing) |
| offhand | 16x16 | 8 x N poses | columns = facing, rows = pose |

- File name: `<symbol>_<cellW>x<cellH>.png`. The name declares the **cell**
  size; the sheet's pixel width/height give the frame count, packed row-major
  (the same convention as `mh_menu_sel_28x16.png` = 8 tiles of 28x16). Symbol is
  `mh_<slot>_<item>` (e.g. `mh_head_helm_16x16.png` -> symbol `mh_head_helm`);
  cell height must be a multiple of 8 (converter/packer rule).
- Anchor convention: cell center. body/head/shadow anchor `(8,8)` = player
  center; weapon/offhand anchor `(16,16)` = grip/pivot in the cell.
- Palette: transparent = mask 0; black/dark/light/white = shades 0..3 exactly
  as `tools/gen-art.py` (1:1 with the L4 triplane levels). No new colors.

### Base sheet (draw-over template)

`docs/art/` holds the canonical template, regenerated by
`python3 tools/gen-base-sheet.py` (`make base-sheet`):

| file | content |
|---|---|
| `player_base_16x16.png` | **the base template**: one sheet, 128x16, all 8 player angles; facing 0 filled with the current silhouette, 1..7 blank |
| `guide_player_base_4x.png` | 4x guide: direction labels (E..NE), cell grid, anchor crosses (8,8), palette swatches |

Workflow for a new player/equipment set: copy `player_base_16x16.png`, draw the
8 angles (one per cell, same cell size), keep the palette, save as
`images/equip/<set>_16x16.png`, add a one-record JSON (`slot: "player"`), run
`make gen`. Layered items (head/body/weapon) follow the same row layout when
the split bead lands.

## Item record (JSON)

`data/equipment/<slot>_<item>.json`:

```json
{
  "id": "head_helm",
  "slot": "head",
  "sheet": "mh_head_helm",
  "cell": [16, 16],
  "anchor": [8, 8],
  "order": "facing",
  "frames": 8,
  "poseMap": { "idle": 0, "stun": 0 },
  "flags": []
}
```

- `order: "facing"` = one frame per facing; `order: "facing*pose"` = the
  weapon table above.
- `poseMap` missing keys fall back to `idle`.
- Equipment **sets** (`data/equipment/sets/*.json`) map slot -> item id; the
  active set is game state (weapon pick already exists; head/body picks land
  with the menu epic).

## Pipeline

1. `tools/gen-equipment.py` (new) reads `data/equipment/**`, validates schema,
   writes `src/generated/equip_meta.hpp` (sheet symbols, cell sizes, frame
   index tables) and the `raw_t` catalog blob.
2. `tools/gen.sh` adds `rm -f fxdata/equip/Sprites.txt` +
   `convert-sprite.py ../images/equip -s 4 -o ../fxdata/equip/`, includes
   `fxdata/equip/Sprites.txt` from `fxdata.txt`.
3. `tools/fxdata_manifest.py` GENERATED_GLOBS += `images/equip/*.png`,
   `fxdata/equip/Sprites.txt`, `data/equipment/*.json` as inputs.
4. Determinism gates as usual (`make gen-check`).

## Render

```cpp
// slot loop; anchors/pose/frame from generated tables, no weapon branches
for (slot in {shadow, body, head, weapon, offhand}) {
    it = equipSet[slot];
    if (!it) continue;
    pose = poseOf(p, g);                       // table
    sprDraw(it.sheet, x + it.dx[pose][dir] - it.cx,
                     y + it.dy[pose][dir] - it.cy,
                     FRAME(it.frame[pose][dir]));
}
```

Dynamic offsets that must stay mock-exact (attack reach scaling, whirl orbit)
are computed per frame exactly as today and passed as an extra offset; the
catalog only owns shapes, anchors and frame selection. A later bead can bake
per-facing arc frames and delete `mulQ4`/`cos256` from the player path.

## Budget

- Cart: sheets are small (16x16 triplane ~ 200-400 B/frame; 24-frame weapon
  sheet ~8-10 KB). Cart image is 30.7 KB of 16 MB — negligible.
- Flash: net win expected — branch code, anchor math and frame picks move to
  generated tables (the current weapon branches are part of `main`'s 13.9 KB).
