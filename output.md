# monhun-ardu-dlp.1 — hql.1 schema v2: quest goals + material rewards in gen/data/host

Record v2 ABI, generator and host logic land with behavior unchanged (all
quests stay kill-only, no materials authored). Bead `monhun-ardu-dlp.1`, epic
`monhun-ardu-dlp`. Not committed: orchestrator stages/commits between waves.

## ABI (docs/quests-shops.md "Quests (content model)")

Blob VERSION 2, header 8 B unchanged, records 9 B little-endian:

```
id u8, goalKind u8 (0 kill / 1 gather), target u8 (MonsterKind for kill /
item idx for gather), need u8, rewardZenny u16, rewardItem u8
(itemIdx + 1, 0 = none), rewardCount u8, unlockFlag u8
```

Offsets emitted: `DEF_ID_OFF 0`, `DEF_GOAL_OFF 1`, `DEF_TARGET_OFF 2`,
`DEF_NEED_OFF 3`, `DEF_REWARD_ZENNY_OFF 4 (u16)`, `DEF_REWARD_ITEM_OFF 6`,
`DEF_REWARD_COUNT_OFF 7`, `DEF_UNLOCK_OFF 8`; plus `GOAL_KILL 0` /
`GOAL_GATHER 1`. Kill `TARGET_*` values unchanged.

## What changed

- `tools/gen-quests.py`: schema v2 keys `goalKind/target/need/rewardZenny/
  rewardItem/rewardCount/unlockFlag`; `goalKind` in kill|gather; kill target
  from `TARGET_NAMES`, gather target validated against `data/items.json`
  (`load_item_ids`, source order == item index); `rewardItem` optional
  (item id -> idx+1) and `rewardCount` required 1..255 with it (and rejected
  without it); emits `GOAL_*`, v2 `DEF_*` offsets, `VERSION 2`, 9 B records.
- `data/quests/*.json` (3): converted to v2, kill-only, `rewardItem` omitted.
- `tools/tests/test_gen_quests.py` + `tools/tests/fixtures/gen_quests/clean`:
  fixture quests to v2 + a fixture `data/items.json`; expected structs
  (`<BBBBHBBB`), meta constants, blob length 26, dump text updated; new cases
  for gather index encoding, unknown goal/gather target, rewardItem/count
  pairing, and index+1 packing.
- `src/quest.hpp`: reads the 9 B record (goalKind/target/rewardZenny/
  rewardItem/rewardCount/unlockFlag).
- `src/quest_state.hpp`: `QuestDef` v2 fields; `questAddProgress(save, n)`
  (clamped 255) replaces `questAddKill`; `questTurnIn(save, quest, need,
  rewardZenny, rewardItem, rewardCount)` pays zenny then
  `saveItemAdd(save, rewardItem - 1, rewardCount)` when `rewardItem != 0`.
- `src/screen_state.hpp`: `ACTION_TURN_IN_QUEST` passes `row.recipe[0]`
  item/count (board recipe zeroed for now) -> still zenny-only.
- `src/app_setup.hpp`: arms `g.questGoalKind` from `def.goalKind` (and
  `g.questTarget` from `def.target`).
- `src/core/game.hpp`: `int8_t questGoalKind` (-1 none) beside `questTarget`.
- `src/core/player.hpp`: `newGame` resets `questGoalKind = -1`.
- `tst/quests_test.hpp`: v2 call sites; `questAddProgress`; material payout +
  255-clamp cases; gather-progress clamp; `newGame` resets goal kind.
- `tst/fxdatatest/quests_test.hpp`: v2 field names + goalKind/material asserts
  (device suite still kill-only, 53/0).
- `docs/quests-shops.md`: content model block updated to v2.
- `src/generated/quest_meta.hpp`, `fxdata/tables/quests.bin` (and the packed
  FX image / header / manifest): regenerated by `make gen`; never hand-edited.

## Deviations / notes

- The first local `make gen-check` failed on `fxdata-data.bin`, `fxdata.bin`,
  `manifest.json`, `equip.bin`, `equip_meta.hpp`, `zone_meta.hpp` — pre-existing
  platform drift in the checked-out generated set (Pillow/sprite output), not
  caused by this bead. A regen rewrote those to the local-toolchain bytes; two
  further `make gen-check` runs PASS. They are staged in the working tree with
  the rest of the generated set (orchestrator `git add -A`).
- `tst/fxdatatest/quests_test.hpp` was not named in the bead text but is an
  ABI consumer (`QuestDef.reward/.targetKind`); updated so the device suite
  keeps compiling. Verified `make fxtest-headless FXTEST_ONLY=test_quests`.
- `fxdata.bin` grew because the quests raw_t payload is part of the single FX
  image; flash growth is the firmware code/data delta above, not the cart.
